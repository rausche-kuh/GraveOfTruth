# Valheim mods

A workspace for BepInEx 5 / HarmonyX plugins for Valheim. Each mod is a top level directory with
its own `CLAUDE.md`; the build, the reference assemblies and the scripts are shared.

**Mods:** `GraveOfTruth/` — makes dying embarrassing. `OdinsMissingPatch/` — configurable QOL
tweaks. `ThisIsValheim/` — doors are kicked open. `ImmersiveEntrance/` — dungeon entrances show the
dungeon behind them. `OdinsTree/` — bless a tree so a tree house on it is safe. `OdinsCompass/` — a
wearable compass that points to the nearest boss, dungeon or ore. `OdinsPaths/` — a road network
grows across the world (server side, not released yet).

## Layout

| Path | What |
| --- | --- |
| `<Mod>/` | One mod: `<Mod>.csproj` (`AssemblyName` + `RootNamespace` only), `src/`, `assets/`, `package/`, `README.md`, `CLAUDE.md`. |
| `<Mod>/ROADMAP.md` | What comes next, the game facts each entry still has to check, and the known bugs. |
| `<Mod>/docs/` | Design notes, mechanics and verified game facts, one file per topic, indexed by the mod's `CLAUDE.md`. |
| `<Mod>/package/` | What Thunderstore gets: `manifest.json`, `icon.png`, `README.md` (the mod page), `CHANGELOG.md`; plus `publish.json` (categories per site, not zipped). |
| `images/` | Preview screenshots and clips for the mod pages, linked by raw GitHub URL; not zipped. |
| `Directory.Build.props` | The shared build: target framework, `lib/` references, publicizer, `src/` and `assets/` globs, `src/Dev/` for Debug only. |
| `scripts/` | `setup`, `deploy`, `bump`, `package`, `decompile`, `clean` (`.ps1` + `.sh`), `publish` and `icon` (`.sh` only). Overview in `scripts/README.md`. |
| `docs/` | Repo wide detail: `environment.md` (game, build, mod manager, bundles, other people's mods), `scripts.md` (every flag, troubleshooting), `releasing.md` (bump, package, preview images, publish). |
| `lib/`, `decompiled/`, `dist/`, `Valheim.props` | Generated by the scripts. Gitignored — never commit game assemblies. |

## Commands

```bash
./scripts/setup.sh       # once, and after every Valheim update
./scripts/deploy.sh      # build + install every mod into the profile (-c Debug for src/Dev/)
./scripts/bump.sh        # raise a mod's version for a release
./scripts/package.sh     # dist/<Mod>-<version>.zip per mod
./scripts/publish.sh     # upload what is not on Thunderstore/Hexium yet
./scripts/decompile.sh   # game source into decompiled/ for API lookup
./scripts/clean.sh       # bin/, obj/, dist/  (--deployed, --all for more)
```

Windows has the same as `.\scripts\*.ps1`, minus `publish` and `icon`. `deploy`, `package` and
`clean` take mod names and default to every mod; `bump` takes one mod and asks for whatever it was
not given. `dotnet build <Mod>/<Mod>.csproj` works once setup has run; there is no solution file.

## Environment facts

Details and the rest in `docs/environment.md`.

- Unity **6000.0.75f1** (Mono), BepInEx **5.4.x**, target framework `net472`.
- Game code is in **`assembly_valheim.dll`** (`Assembly-CSharp.dll` is a stub): grep
  `decompiled/assembly_valheim/` for game types.
- `assembly_valheim` / `assembly_utils` are publicized, so private game members are reachable.
- Prefabs and UI layout live in the addressable bundles under `StreamingAssets/SoftRef/Bundles/`
  and can be read with UnityPy without running the game (recipe in `docs/environment.md`).
- Mod manager is **Gale**; each mod deploys to `<ProfileDir>/BepInEx/plugins/rauschekuh-<Mod>`.
- `~/Documents/Code/test/othervalheimmods/` holds other people's mods to learn from. Read them
  before reinventing a patch; **never copy code out of them** (licenses in `docs/environment.md`).

## Conventions

- A mod is **any top level directory holding `<Name>/<Name>.csproj`**; directory, project and
  assembly name must match. Nothing needs registering ("Adding a mod" in `scripts/README.md`).
- Build settings belong in `Directory.Build.props`, not in a mod's csproj; its item globs resolve
  against each mod directory, shared paths use `$(MSBuildThisFileDirectory)`.
- `VERSION` in a mod's plugin source is the single source of truth for its version. **Only bump it
  for an actual Thunderstore release**, never as part of a code change, and only with
  `scripts/bump.sh`: it raises `VERSION`, `manifest.json` and the changelog's `## Unreleased`
  heading together. Mods version independently.
- Test helpers (dev console commands and the like) go in the mod's `src/Dev/`, which only Debug
  builds compile; `package` (always Release) leaves them out.
- Everything in a mod's `assets/` is copied next to its DLL and shipped; load it from beside the
  assembly at runtime.
- `<Mod>/package/CHANGELOG.md`: add an entry under `## Unreleased` whenever a change alters what a
  player sees, in the same commit, written for players (what changed in the game, not which method
  was patched).
- `<Mod>/package/README.md` is the Thunderstore page and renders standalone: what the mod does,
  install, multiplayer/compatibility — no build instructions, no repo-relative links, no changelog.
- Patches are plain `[HarmonyPatch]` classes nested in the plugin class; keep them small and
  null-guard everything (`Player.m_localPlayer` is frequently null).
- Check the BepInEx pack in `manifest.json` `dependencies` before publishing (see
  `docs/releasing.md`).

## Keeping the docs small

`CLAUDE.md` files and READMEs are loaded often, so keep them short: a `CLAUDE.md` at most ~6 KB
(purpose, state, a docs index, the rules that always apply, a one-line-per-file source map), a
dev `README.md` at most ~3 KB. Anything longer — mechanics, design, verified game facts, full
file descriptions — goes in `docs/` (the mod's, or the root one for repo wide topics) and is linked
from the index. Thunderstore pages (`package/README.md`) are exempt: they must stand alone.
